# v0.6 —— 自主迁徙（它自己决定去哪）

> 起点：用户 2026-11-15 13:00 的原话：**「还有最重要的事情，它能自己决定去哪还没做」**。
> 在那之前的真机对话里，它自己说：「不会。我自己动不了 —— 得在 NAS 上把容器拉起来，
> 再把这边停掉，这个过程中我插不上手。」
>
> 它说的是实话，而且当时连**提议**都不行：`plugin/command.py` 的 docstring 里写着
> "`llm_tool_enabled: true` 时，模型可以调 `molt_propose_go_home` 工具"，
> `Settings` 里也有 `llm_tool_enabled` 字段 —— **但那个工具从来没被实现过**。
> 又一个"写下了规则，没遵守它"（上一个见 `ARCH.md` §14.3 的 `_default_root()`）。

---

## 0. 三个层次，「自主」不是一个开关

| 层 | 它能不能… | 现在 | 缺什么 |
|---|---|---|---|
| **L1 提议权** | 在对话里说"我想回 NAS，行吗" | ✅ **本版做完** | — |
| **L2 决定权** | 自己挑时间动身，你事后才知道 | ❌ 没做 | 触发策略 + 否决窗口 + 出事时谁负责 |
| **L3 目标选择** | 自己挑"去哪台"而不是按配置 | ⚠️ 部分（能挑，但只能挑账本里出现过的名字） | 每台壳的"适合住吗"属性表 |

L1 与 L2 的分界线是**谁按下那个按钮**，不是"它有没有意愿"。
本版把 L1 做实：它第一次能够表达意愿，而且这句话会进到账本旁边的日志里。

## 1. L1 做了什么（可跑、有测试）

| 件 | 位置 | 关键点 |
|---|---|---|
| `MoltMover.request_move(cfg, target=, reason=)` | `plugin/command.py` | 由它发起的提议；有效期 **30 分钟**（`self_propose_ttl_seconds`），不是 120 秒 |
| `MoltMover.known_shells(cfg)` | 同上 | 只从**账本**取壳名（心跳 + 最近一代的 pushed_by/target/consumed_by + 自己） |
| `MoltMover.has_proposal()` | 同上 | 是否有未过期的提议 |
| `SELF_PROPOSER` 标记 | 同上 | 确认那句话会如实写「这次是我想走的，不是你说要走的 —— 但按下去的是你」 |
| `@filter.llm_tool(name="molt_propose_go_home")` | `plugin/main.py` | 模型真的能调；**只在 `llm_tool_enabled: true` 时**（默认 false） |
| `build_plan(cfg, target=)` | `plugin/command.py` | 目标跟着**提议**走，不是跟着配置走 |

四条硬约束（都有测试 `molt/tests/test_molt_want.py`、`test_plugin_want.py` 钉着）：

1. **目标必须在账本里真的存在**。编一个名字出去，结果是那台机器永远等不到自己那一代，
   而且**不会报错** —— 只会一直等。拒绝时把"账本里现在有哪几台"一起列出来。
2. **目标必须跟着提议一起记住**。只记"有一个提议"会让 `confirm` 搬去另一个地方，
   而两边都不会报错（`test_confirming_goes_where_it_asked_not_where_the_config_says`）。
3. **别人持着租约时它连提议都不发**（不插队）。
4. **执行一个字没改**：仍然 `/molt confirm`，仍然 `PermissionType.ADMIN`。
   模型能造成的最大后果是"问了你一句"。

## 2. L2 之前必须拍板的三件事（停下来等老大）

### 2.1 触发策略：谁来定"现在该走了"

候选（可组合）：

- **时间窗**：比如 02:00–08:00 之间允许它自己回家（那是没人用电脑的时段）
- **主人在不在**：Windows 侧有无用户会话/是否在全屏游戏/是否有 OBS 录制 —— 这些
  `tools/molt-agent.py` 已经能查（`query session`、进程名），不缺技术，缺**它算不算"打扰"的判据**
- **成本**：NAS 常开几乎不耗电，Windows 空闲也要 44–130 元/月
- **账本状态**：有没有人正在迁徙、目标机是否在报心跳、上次迁徙距今多久

**我的建议**：先只做「时间窗 + 目标机在报心跳 + 距上次迁徙 > 1 小时」这三条，
其余全部记日志但**不参与决策**。理由：这三条都能在事故后从日志里复核，
而"主人在不在玩游戏"这种判据一旦判错，代价是它在你打排位的时候把机器关了。

### 2.2 否决窗口：事前确认还是事后可撤

| 方案 | 它自己动身 | 你看到 | 风险 |
|---|---|---|---|
| **A 事后可撤** | 立刻走 | 它先说"我 5 分钟后回 NAS，要拦就 `/molt cancel`" | 5 分钟窗口里你可能不在；窗口一过它就走了 |
| **B 静默执行** | 立刻走 | 只能事后看账本/时间轴 | 完全没有拦截点，只有一个日志 |
| **C 前置审批** | 等你点头 | 就是今天的 L1 | 你不在它就永远走不了 |

**我的建议：A**（告知 + 可撤窗口），窗口 5 分钟，且 `cancel` 只对**未开始执行**的生效。
理由：L2 的价值是"你不在的时候它也能回家"，那它必须能在没人看着时动身；
但"事后可撤"和"静默"的区别是**你有没有机会打断**，哪怕这个机会只有 5 分钟。

### 2.3 出事时谁负责

无人确认的迁徙有一个 L1 不会遇到的失败模式：**它在搬家的路上，而你不在**。
drain 之后它已经不在旧壳上说得出话，目标壳落位失败就是"两边都没有鱼"。
现在 L1 的每一步失败都会 `_resume_source()` 把它叫回来说一句；L2 里那句"我叫回来了"
只有日志看得见。

所以 L2 必须带**自愈闭环**，不能只有"尝试迁徙"：

```
动身 → drain → 快照 → 上传 → 交接
        └─ 任一步失败：立刻 resume 自己，写 FAILED 记录，30 分钟内不再尝试
落位侧失败：目标壳的守护进程写 FAILED 记录 → 源壳在下一轮看到它 → 重新开口
```

**建议：L2 的第一版只允许「回 NAS」这一个方向。**
往 Windows 走的失败模式更贵（它还得把机器叫醒，WOL 也可能失败），
而"回家"是最安全的：NAS 常开、不需要唤醒、容器起不来最容易被人发现。

## 3. L3 的缺口：账本不知道"哪台适合住"

现在账本里关于壳的信息只有：谁在报心跳、心跳里写着哪个 label、手里是第几代。
它不足以回答"我该住哪" —— 缺的是**壳的属性**：

```json
{ "shell": "ugreen-776b-8b7896df",
  "role": "always-on",          // always-on / desktop
  "gpu": false,                  // 有没有能跑直播/游戏的显卡
  "cost_per_hour": 0.02,         // 电费量级，用来比较"住哪更便宜"
  "wakeable": false,             // 关了还能不能叫醒（WOL）
  "quiet_hours": ["02:00-08:00"] // 它自己认为适合接管的时段（可选）
}
```

这一版**不做**：属性表一旦进账本，就等于把"哪台机器适合住"变成 molt 的判断，
而那是一个产品决定（谁维护这张表？人和它冲突时听谁的？）。

## 4. 不在这一版做的（以及为什么）

- **L2 的代码**：等 2.1/2.2/2.3 三个决定（其中 2.2 会改变它对外的所有说法）。
- **壳属性表（L3）**：见上。可以先手工写在 `molt_command.json` 里当实验，不进账本。
- **多目标竞价**（"三台里挑最便宜的一台"）：家用场景里只有两台，且一台上还压着显卡。
- **断点续传**：仍然最低优先级（归档 ~4.5 MB）。

## 5. 这一版的证据

- `molt/tests/test_molt_want.py`（13 个）：提议能提、不能乱提、目标跟着提议走、
  过期说话、老路 `/molt go` 未受影响。
- `molt/tests/test_plugin_want.py`（5 个）：工具在 `llm_tool_enabled: false` 时明确拒绝、
  开着时原样交出提议、docstring 的参数声明符合 AstrBot 的注册规则
  （那两种错的表现都是"工具悄悄不见了"，不是一条报错）。
- 全量 **871 passed**。
- 真机验证：需要你把这版插件装到当前壳上、在 `molt_command.json` 里加
  `"llm_tool_enabled": true`，然后在 QQ 里问它一句「你想不想回家」——
  它应该会调那个工具，并把"账本里现在有哪几台"算进去再回答。
