# v0.6 —— 自主迁徙（它自己决定去哪）

> 起点：用户 2026-11-15 13:00 的原话：**「还有最重要的事情，它能自己决定去哪还没做」**。
> 在那之前的真机对话里，它自己说：「不会。我自己动不了 —— 得在 NAS 上把容器拉起来，
> 再把这边停掉，这个过程中我插不上手。」
>
> 它说的是实话，而且当时连**提议**都不行：`plugin/command.py` 的 docstring 里写着
> "`llm_tool_enabled: true` 时，模型可以调 `molt_propose_go_home` 工具"，
> `Settings` 里也有 `llm_tool_enabled` 字段 —— **但那个工具从来没被实现过**。
> 又一个"写下了规则，没遵守它"（上一个见 `ARCH.md` §14.3 的 `_default_root()`）。

---

## 0. 三个层次，「自主」不是一个开关

| 层 | 它能不能… | 现在 | 缺什么 |
|---|---|---|---|
| **L1 提议权** | 在对话里说"我想回 NAS，行吗" | ✅ **本版做完** | — |
| **L2 决定权** | 自己挑时间动身，你事后才知道 | ❌ 没做 | 触发策略 + 否决窗口 + 出事时谁负责 |
| **L3 目标选择** | 自己挑"去哪台"而不是按配置 | ⚠️ 部分（能挑，但只能挑账本里出现过的名字） | 每台壳的"适合住吗"属性表 |

L1 与 L2 的分界线是**谁按下那个按钮**，不是"它有没有意愿"。
本版把 L1 做实：它第一次能够表达意愿，而且这句话会进到账本旁边的日志里。

## 1. L1 做了什么（可跑、有测试）

| 件 | 位置 | 关键点 |
|---|---|---|
| `MoltMover.request_move(cfg, target=, reason=)` | `plugin/command.py` | 由它发起的提议；有效期 **30 分钟**（`self_propose_ttl_seconds`），不是 120 秒 |
| `MoltMover.known_shells(cfg)` | 同上 | 只从**账本**取壳名（心跳 + 最近一代的 pushed_by/target/consumed_by + 自己） |
| `MoltMover.has_proposal()` | 同上 | 是否有未过期的提议 |
| `SELF_PROPOSER` 标记 | 同上 | 确认那句话会如实写「这次是我想走的，不是你说要走的 —— 但按下去的是你」 |
| `@filter.llm_tool(name="molt_propose_go_home")` | `plugin/main.py` | 模型真的能调；**只在 `llm_tool_enabled: true` 时**（默认 false） |
| `build_plan(cfg, target=)` | `plugin/command.py` | 目标跟着**提议**走，不是跟着配置走 |

四条硬约束（都有测试 `molt/tests/test_molt_want.py`、`test_plugin_want.py` 钉着）：

1. **目标必须在账本里真的存在**。编一个名字出去，结果是那台机器永远等不到自己那一代，
   而且**不会报错** —— 只会一直等。拒绝时把"账本里现在有哪几台"一起列出来。
2. **目标必须跟着提议一起记住**。只记"有一个提议"会让 `confirm` 搬去另一个地方，
   而两边都不会报错（`test_confirming_goes_where_it_asked_not_where_the_config_says`）。
3. **别人持着租约时它连提议都不发**（不插队）。
4. **执行一个字没改**：仍然 `/molt confirm`，仍然 `PermissionType.ADMIN`。
   模型能造成的最大后果是"问了你一句"。

## 2. L2 之前必须拍板的三件事（2.1 / 2.2 已定案，2.3 见 §2.3.1）

### 2.1 触发策略：触发源是**接口**，不是一串 if

**已定案（2026-11-15，老大拍板）**：不把"什么时候该走"写死成一个判断，
而是先把**触发源**做成一个开口，未来每一种"想搬的起因"都往同一个口子里灌。

| 触发源 | 谁让它发生的 | 今天的状态 |
|---|---|---|
| `human` | 人在聊天里敲 `/molt go` | ✅ 一直有 |
| `self` | 它自己觉得该换机器了（`molt_propose_go_home`） | ✅ v0.6 L1 |
| `utterance` | 主人一句话（"去打会儿游戏吧"），它把那句话翻译成一次搬迁 | 🔧 接口已通，判据未实装 |
| `schedule` | 到点了（`0 3 * * *` 这种） | 🔧 接口已通，判据未实装 |

三条设计规矩：

1. **新增一个触发源，不新增一条执行路径。** 四个来源都调同一个
   `MoltMover.request_move(source=...)`，所以 fencing、租约、"先死后生"、
   `/molt confirm` 这些性质只需要在一个地方成立。
2. **来源不明就拒绝。** `source` 不在表里时它连提议都不发。理由：确认时那句
   "这次是谁提的"是要给人看的，**不能靠猜**；猜错的代价是主人在最需要看清
   谁想搬的时候，看到一句假话。
3. **配置里写了、代码还没实装的触发源，是阻塞项而不是被忽略。**
   有人在 `molt_command.json` 里写 `"triggers": {"cron": "0 3 * * *"}`，
   他的意思肯定是"凌晨三点去"。默默忽略的话，那条规则**永远不会生效、
   也不会有任何提示** —— 他会以为配好了，直到某天发现鱼没动。

**留给未来的接口点只有两个**：`MoltMover.move_policy_refusals()`（只产出"现在不能搬"的
理由，**不产出动作**）与 `request_move(source=...)` 的来源声明。
`schedule` 实装那天，加进前者的是"现在到点了吗"；"那句话"实装那天，加进去的是
"主人的意思是去还是不去"。两者都不会碰到执行那一步。

**今天刻意不做的**：时间窗判定、主人是否在打游戏、成本计算。不是技术问题，
是**它们都还没有可信的判据** —— 见下面 2.1.1。

#### 2.1.1 为什么"主人在不在玩游戏"今天不能进判据

`tools/molt-agent.py` 已经能查 `query session`、进程名、OBS 是否在录（真机上验过），
所以这不是缺技术。缺的是一个**能承担后果的判据**：

- 判"在玩游戏"靠进程名 → 他开着游戏挂机、人在客厅，它就不搬了；反过来他真在打排位，
  进程名可能只是启动器。
- 判"不在用电脑"靠空闲时间 → 挂了下载任务，机器整晚都"忙"，它永远不回家。
- 判错一次的方向是不对称的：**该搬没搬**只是少回家一晚；**不该搬搬了**是在人打排位时
  关掉这台机器。后者属于"宁可不动"的那一类。

所以这一条要等真正的遥测（窗口焦点、输入空闲、是否全屏独占 + 用户显式开关），
而不是靠猜进程名。**先留接口，后补判据。**

### 2.2 否决窗口：**已定案 C（前置审批）**（2026-11-15 老大拍板）

| 方案 | 它自己动身 | 你看到 | 风险 |
|---|---|---|---|
| A 事后可撤 | 立刻走 | 它先说「我 5 分钟后回 NAS，要拦就 `/molt cancel`」 | 5 分钟窗口里你可能不在；窗口一过它就走了 |
| B 静默执行 | 立刻走 | 只能事后看账本/时间轴 | 完全没有拦截点，只有一个日志 |
| **C 前置审批（已选）** | **等你点头** | 就是今天的 L1 | 你不在它就永远走不了 |

**为什么选 C**：这套系统里最贵的错误都是「看起来像成功」的那一类，而无人确认的
迁徙多出一种 L1 不会遇到的失败模式 —— **它在搬家的路上，而你不在**。
选 C 之后，「它自己决定去哪」这件事的后果面被压到最小：**它能提，但它不能出门。**

代价说清楚，不许含糊：

- **你不在的时候它走不了。** L2 原本想解决的就是「你出差三天，它想回家」，
  现在这条不解了。这不是 bug，是选的。
- 所以 L2 剩下的价值不是「自动迁徙」，而是**在合适的时机提醒你**：
  「我在一台随时会被关掉的机器上，你那台常开的 NAS 现在空着，要不要我回去？」
  —— 一句提醒，比一次自动迁移便宜得多，也安全得多。
- 提议 30 分钟过期（`self_propose_ttl_seconds`）。过期就是什么都没发生，
  **不重试、不排队、不留一个"待执行"**。

**这一条有测试钉着**（`molt/tests/test_molt_want.py`）：
`test_a_proposal_only_ever_asks_and_never_runs` 与
`test_an_expired_proposal_simply_vanishes`。前者的判据是「提议存在，但一个执行计划都没被造出来」，
后者的判据是「时间过去，提议消失，什么都没有发生」。**把「不做某件事」写进测试**，
因为下一个人很容易把「让它自己走」当成一个贴心的改进。

### 2.3 出事时谁负责

无人确认的迁徙有一个 L1 不会遇到的失败模式：**它在搬家的路上，而你不在**。
drain 之后它已经不在旧壳上说得出话，目标壳落位失败就是"两边都没有鱼"。
现在 L1 的每一步失败都会 `_resume_source()` 把它叫回来说一句；L2 里那句"我叫回来了"
只有日志看得见。

所以 L2 必须带**自愈闭环**，不能只有"尝试迁徙"：

```
动身 → drain → 快照 → 上传 → 交接
        └─ 任一步失败：立刻 resume 自己，写 FAILED 记录，30 分钟内不再尝试
落位侧失败：目标壳的守护进程写 FAILED 记录 → 源壳在下一轮看到它 → 重新开口
```

### 2.3.1 选 C 之后，真正的锐齿挪到了「关机」上

C 只解决了「它能不能自己动身」，没有解决「动身之后这台机器会怎样」。
今天 `tools/molt-agent.py` 在鱼离开后会自己执行：

```
shutdown /s /t <shutdown_delay_seconds> /c "molt: 它已经走了，这台机器休息"
```

它**不检查任何东西**：正在录的 OBS、正在跑的游戏、编辑器里没保存的文档、
下载到一半的文件 —— 30 秒后一起没了。这跟"要不要让它自己搬"是两个问题，
而人很容易以为"反正要我问了才走，那肯定安全"。

三条可选的边界（**待老大拍板，本版不动**）：

| 方案 | 关机前做什么 | 代价 |
|---|---|---|
| **A 先看再关**（我推荐） | 查 OBS 是否在录、`playing_processes` 白名单里有没有进程、有没有 `shutdown /a` 之外的活动；命中就**只发一条通知，不关** | 要多维护一份进程名单，且"没保存的文档"技术上查不到（只能靠"程序在跑"近似） |
| B 一律关 | 保持今天的行为 | 简单，丢东西时无法解释 |
| C 干脆不关 | `shutdown_after_leave: false`，关机永远由人来做 | 最安全，但"回家"这件事就少了它"顺便把机器关掉"的那一半价值 |

**已定案（2026-11-15，老大拍板）：把它拆成两个问题，交给人分别回答。**

- 第一个问题（要不要走）：`/molt go` → `/molt confirm`。这是 L1/L2 那套，不变。
- 第二个问题（那台机器关不关）：`/molt shutdown` 或 `/molt keep`。
  **它落成账本里的一张票据（`power.json`），不落成一次自动关机。**

实现要点（都有测试 `molt/tests/test_power_ticket.py` 钉着）：

| 决定 | 为什么 |
|---|---|
| 票放在 `power.json`，不进 `state.json` | 账本记的是「谁在哪一代取走了什么」，是交接历史；一张「允许关掉 X」是**当前状态**，和心跳同一类 |
| **没有票 = 不关**（`power_requires_permission: true` 是新默认） | 判错的方向不对称：该关没关只是多耗一晚电，不该关关掉了是人的工作被清掉 |
| 票读坏了也当作「没票」 | 一张坏票绝不能变成一次关机 |
| 关完/决定留着之后立刻销票 | 否则它下次又生效，而人早就忘了自己什么时候点过 |
| `power_requires_permission: false` 仍保留 | 想回到"走了就自动关"的人可以显式关掉，但那不再是默认 |

**这条改动把 §2.3 的"出事谁负责"削掉了一大半**：人点一次「走」不再顺带丢掉别的东西。
剩下那一小半是「它自己提的、你确认了」这条路上的心理负担，那属于 L2 的 UI 文案问题。

**建议：L2 的第一版只允许「回 NAS」这一个方向。**
往 Windows 走的失败模式更贵（它还得把机器叫醒，WOL 也可能失败），
而"回家"是最安全的：NAS 常开、不需要唤醒、容器起不来最容易被人发现。

## 3. L3 的缺口：账本不知道"哪台适合住"

现在账本里关于壳的信息只有：谁在报心跳、心跳里写着哪个 label、手里是第几代。
它不足以回答"我该住哪" —— 缺的是**壳的属性**：

```json
{ "shell": "ugreen-776b-8b7896df",
  "role": "always-on",          // always-on / desktop
  "gpu": false,                  // 有没有能跑直播/游戏的显卡
  "cost_per_hour": 0.02,         // 电费量级，用来比较"住哪更便宜"
  "wakeable": false,             // 关了还能不能叫醒（WOL）
  "quiet_hours": ["02:00-08:00"] // 它自己认为适合接管的时段（可选）
}
```

这一版**不做**：属性表一旦进账本，就等于把"哪台机器适合住"变成 molt 的判断，
而那是一个产品决定（谁维护这张表？人和它冲突时听谁的？）。

## 4. 不在这一版做的（以及为什么）

- **L2 的代码**：等 2.1/2.2/2.3 三个决定（其中 2.2 会改变它对外的所有说法）。
- **壳属性表（L3）**：见上。可以先手工写在 `molt_command.json` 里当实验，不进账本。
- **多目标竞价**（"三台里挑最便宜的一台"）：家用场景里只有两台，且一台上还压着显卡。
- **断点续传**：仍然最低优先级（归档 ~4.5 MB）。

## 5. 这一版的证据

- `molt/tests/test_molt_want.py`（13 个）：提议能提、不能乱提、目标跟着提议走、
  过期说话、老路 `/molt go` 未受影响。
- `molt/tests/test_plugin_want.py`（5 个）：工具在 `llm_tool_enabled: false` 时明确拒绝、
  开着时原样交出提议、docstring 的参数声明符合 AstrBot 的注册规则
  （那两种错的表现都是"工具悄悄不见了"，不是一条报错）。
- 全量 **871 passed**。
- 真机验证：需要你把这版插件装到当前壳上、在 `molt_command.json` 里加
  `"llm_tool_enabled": true`，然后在 QQ 里问它一句「你想不想回家」——
  它应该会调那个工具，并把"账本里现在有哪几台"算进去再回答。
