# 陌生人冷启动复核（v1.1，2026-11-15）

问题：**一个从没听过 molt 的人，只照 README + `docs/INSTALL.md`，能不能把它装起来、能不能看见"它搬过几次家"？**

做法是三轮，一轮比一轮狠。第一轮是"我照文档敲"，第三轮是"**我只从 PyPI 装一个下
载来的轮子**，仓库里有什么与我无关"。

---

## 第一轮：照文档敲，撞到四处墙

用 `pip install molt-handoff`（当时 1.0.1）装，然后逐条照 `docs/INSTALL.md` 走。

| # | 撞到什么 | 属于谁的错 |
|---|---|---|
| 1 | `molt init --role warden` 打印的下一步是 `python3 -m molt.cli serve`；Windows 上 `python3` 是应用商店占位符（退出码 9009），而 `molt serve` 本来就有 | **产品**：不该教人用一条在目标平台不存在的命令 |
| 2 | `molt init --role agent` 直接失败：`找不到 .../site-packages/tools/molt-agent.py` | **产品**：守护进程住在仓库 `tools/` 下，而 `tools/` 不进 wheel —— 代码位置错，不是文档错 |
| 3 | `molt-agent.py --config ./agent.json --once` → `CommandNotFoundException` | **产品**：脚本不在 PATH 上 |
| 4 | 陌生人**永远没有迁徙记录**，`molt timeline` 只能给一页白纸 | **产品**：验收标准里"能看见迁移过程"没有任何一条路径 |

第 2 条是最严重的：**`pip install` 的人拿到一份配置，却没有一条能跑它的命令**。而
它在本机用 `pip install .` 永远测不出来 —— 因为那时候 `tools/` 就在旁边。

### 修法

- `git mv tools/molt-agent.py molt/daemon/agent.py`（homer 同），`packages = ["molt", "molt.daemon"]`；
  `tools/*.py` 降级成四行垫片（`globals().update(...)` 后调真模块）。
- 新增真入口 `molt agent` / `molt homer`（在 `main()` 里按 argv 分发 —— argparse 的
  `REMAINDER` 子命令**不接管未知开关**，实测试过）。
- `molt init` 的提示改成 `molt serve ...`，仓库备用法放进括注。
- 新增 `molt timeline --demo`：同一套模板 + 琥珀色横幅 + **假壳名**（`nas-box` /
  `my-laptop`；真壳名落到截图里就是信息泄漏）。
- 文档：README 先写「装两样东西，**先选一条路**」；INSTALL 的 `git clone` 降级为
  "想改代码才需要"；cron / 启动项统一成 `molt agent`。

## 第二轮：修完再用 `pip install .` 重走

五步全过（init warden → serve → init agent → doctor → `agent --once`），
`molt timeline --demo` 出一页可看的示例时间轴。

这轮**什么都证明不了**，因为装的还是本地目录。它的价值只有一个：确认修改没把
"仓库里能用"这条路弄坏。

## 第三轮：只从 PyPI 装 —— 13/14

```
pip install molt-handoff==1.1.0        # 下载来的轮子，不是本地目录
molt --no-color agent --config agent.json --once
  → molt: error: argument <命令>: invalid choice: 'agent'
```

**装是装上了，跑却说不认识自己的命令。** 根因：入口只在 `argv[0]` 上认守护进程
名字，而 `molt --no-color agent ...`（全局开关在前）这一行是很自然就会写出来的；
它掉进 argparse，然后报一个"你打错字了"的错 —— 而实际上打错的是我。

### 修法（1.1.1）

入口先把 `--no-color` / `--color` 剥掉再判断。补一条测试钉住
`test_a_global_flag_before_the_daemon_name_still_dispatches`。

## 这条性质怎么保住

`tools/rehearse-install.py` 验的是"仓库能装"，**看不见发布物缺什么**。
所以另有一个只碰上游的：

```
python tools/rehearse-pypi.py                 # 装 PyPI 上最新的，走完十五个检查点
python tools/rehearse-pypi.py --version 1.2.0 # 验指定版本
python tools/rehearse-pypi.py --keep          # 留着 venv 进去看
```

它不读仓库里的任何代码，所以仓库怎么改都影响不了它 —— **这正是它有用的原因**。

### 1.2.0 真的用它验过一次

`v1.2.0` 发出去之后，对 PyPI 上那份轮子跑：**15/15 通过**（新增的两条是
`molt declare` 真写进账本、`molt shells` 真读得回来）。同一轮里这个脚本自己
暴了一个 bug：`report()` 收集二元组却按三元组解包，**全部通过时那行永远不会
执行**，于是它只证明过"成功的样子"，第一次真有失败就直接崩掉 ——
"演练脚本的失败路径从没被执行过"和它要防的那类 bug 是同一个形状。

修法三条：解包改对；只在 `No matching distribution`（CDN 边缘滞后）上重试六次，
别的错一次就报；1.2 的两条新命令进检查点，且不验"命令不报错"而验"账本里真有"。

## 三个顺手记下的坑

1. **PyPI 的 JSON API 比 simple 索引先更新**。发布后几十秒内
   `https://pypi.org/pypi/<name>/json` 已经有新版本，而 `pip install` 仍可能说
   `from versions: 1.0.1` —— 那不是发版失败，是索引还没同步。复核脚本因此显式
   指定 `--index-url https://pypi.org/simple` 且 `--no-cache-dir`。
2. **`/status` 要 `X-Molt-Token`**。不带是 401；401 也说明"账本在"，但验"账本想好没好"
   时必须带上。
3. **`--no-color` 这种全局开关排在子命令前面，是一条真实的用法**，不是刁钻写法。
   凡是"我只认第一个词"的实现，都该被这一条撞一次。
