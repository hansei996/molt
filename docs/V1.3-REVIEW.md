## 判据（三条都满足才算验过）

1. 每一步点下去，**页面上有一句能复述的结论**（不是只有一个变灰的按钮）；
2. 结论里的**数字对得上**（几个插件、多少 KB、哪几个文件）；
3. **失败也看得见**：不勾确认、来源不存在时，页面说得出"为什么不行"。

## 这次抓到的两个真 bug

1. **`undefined 个插件的配置`**（19:27:48）：后端 `do_publish` 返回的 `plugins` 是**数字**，
   前端写 `(res.plugins || []).length`。这种错**没有异常、没有日志**，只有人盯着屏幕才看得见。
   修法：`plugins` 一律名字数组，数量另给 `plugin_count`；前端两者都认；补一条发布物测试。
2. **反馈感太弱**（主人原话：「我试着点了一下，反馈感不强啊，我都不知道是不是同步成功了？」）：
   结果只在 12.5px 小字里、按钮点下去没变化、同步成功后表格被刷成「一样，不用动」，
   **看起来更像什么都没发生**。修法：顶部带时间横幅、按钮进行中改文案、写完之后单独留一份
   写入清单（表格会变，清单不会）。

## 每次改了这三个文件之后怎么重跑

```powershell
# 0) 只改页面/后端，不动生产配置
$py = "C:\Users\13553\AppData\Local\Programs\Python\Python313\python.exe"

# 1) 语法与发布物
node --check plugin\views\sync\app.js
& $py -m pytest molt\tests\test_plugin_bundle.py molt\tests\test_plugin_sync_api.py -q

# 2) 装到 AstrBot 并重载插件（不要整机重启）
Copy-Item plugin\views\sync\* "G:\molt-fish\data\plugins\astrbot_plugin_molt\views\sync\" -Force
Copy-Item plugin\sync_api.py "G:\molt-fish\data\plugins\astrbot_plugin_molt\" -Force
& $py tools\reload-plugin.py astrbot_plugin_molt

# 3) 浏览器里按上表第 1–7 步走一遍（第 8 步永远不点）
```

## 怎么判"这次没验过"

- 点下去**超过 1 秒**页面毫无变化（按钮文案没变、横幅没变）→ 不通过；
- 结论句里出现 `undefined` / `NaN` / `[object Object]` → 不通过；
- 预览之后 `data/config/` 下**多出任何文件** → 不通过（预览必须一个字节都不写）；
- 勾选框不勾也能点「写这 N 个」 → 不通过（前端闸失效）；
- 横幅是绿色但按钮还在转 → 不通过（状态没收尾）。

---

这套动作不靠记性：**它的价值在于"下次改页面时，照着做一遍就够"**。
真正的回归保护还是那两条 pytest + 一条发布物测试；这一页管的是它们管不到的那半。
