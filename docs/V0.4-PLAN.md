## 0. 为什么是这一版

`docs/PLAN.md` §4.2 原来排的版本计划是：

| 版本 | 目标 | 现在 |
|---|---|---|
| v0.1 手工验证 | 数据不坏、Windows 能跑 | ✅ 完成 |
| v0.2 租约 | 证明互斥（epoch / split brain） | ✅ 完成 |
| v0.3 自动化 | 一条命令完成迁徙 / 归巢 | ✅ 完成 |
| **v0.4 硬化** | **故障注入，全部安全失败** | **← 本文件** |
| v0.5 通用化 | 脱离 AstrBot | 未开始 |
| v1.0 开源发布 | 别人能用 | 部分（已上架插件市场、有 CI） |

v0.1–v0.3 已经真机跑通（记录见 `docs/ARCH.md` 与 `docs/SESSION-STATE.md`）。
**所以下一个要补的不是功能，是"它坏的时候会怎么坏"。**

这个判断有一个具体理由：这套系统里最贵的错误全都长得像成功。

- 归档少了一半 → 只要没人算指纹，`tar` 照样能解开一部分
- 落位写到一半 → 目标 `data/` 里有 `data_v4.db`，大小看着也对
- 账本写坏 → 下一次 `load()` 才发现，那时已经没人知道上一次是什么状态

**"看起来像成功"是这一版要消灭的东西。** 每一条持久化写入都必须满足：
要么完整落盘，要么完全不存在 —— 中间态不许被任何读者误认成终态。

## 2. T1 · 打包原子化

**现在的写法**（`molt/transfer.py:107` `make_archive`）：

```python
with tarfile.open(out_path, "w:gz", compresslevel=6) as tf:
    for p in files:
        tf.add(str(p), arcname=rel, recursive=False)
```

`out_path` 是最终名字。进程在 `tf.add` 中间被 SIGKILL（或断电、或盘满），
磁盘上就留下一个**截断的 `gen-000012.tar.gz`**。

它为什么会骗人：

- `molt prune` 的 `list_archives()` 用 `d.glob("gen-*.tar.gz")` 枚举 —— 它会被列出来
- `tarfile.open()` 对截断的 gzip 往往能读出前面几个成员，不报错
- 名字里有代次，看起来"就是那一代"

**改法**：写 `<out_path>.part`，验完（重读核对成员数/字节数）再 `os.replace`。
`os.replace` 同目录内是原子的；跨文件系统会退化成"拷贝 + 删除"，所以 `.part`
必须和 `out_path` 同目录。

> 这条和 `server.py` 里收归档的 `_receive_archive` 是同一个模式 ——
> 那边早就做对了，这边漏了。**同一个正确模式不复制到所有发送方，
> 就等于只有一半是对的。**

## 3. T2 · 落位原子化

**现在的写法**（`molt/transfer.py:366`）：`shutil.copy2(src_file, dst)` 直接写进目标
`data/`。中途失败留下一个**截断的 `data_v4.db`**，而它：

- 文件名对、位置对、`stat().st_size > 0`
- 只有 SQLite 真去打开它才会报 `file is not a database` 或 `database disk image is malformed`

**改法**：

1. 每个文件写 `<dst>.molt-part`，`os.replace` 就位（同一文件系统，原子）
2. 落位开始前写 `.molt-restore-incomplete`（含 generation、时间、目标）
3. 全部完成后删掉它
4. **任何进程在启动 AstrBot 之前，看到这个标记就必须拒绝** ——
   `tools/molt-agent.py` / `tools/molt-homer.py` 的 `do_boot` / `do_start` 各加一道守卫

第 4 条是关键：标记只有被人读到才算数。

## 4. T3 · manifest 校验加固

`manifest.json` 是"这份快照从哪来"的唯一证词，现在 `land` 只检查它**存在**。
要补：

| 字段 | 必须 | 类型 | 不符时 |
|---|---|---|---|
| `generation` | 是 | int | 拒绝：说不清这是第几代 |
| `pushed_by` | 是 | str 非空 | 拒绝 |
| `target_shell` | 是 | str 非空 | 拒绝 |
| `epoch` | 是 | int | 拒绝 |
| `created_at` | 是 | str | 拒绝 |
| `schema_version` | 否 | int | 有就必须是 1 |

另加一条交叉校验：**manifest 的 `generation` 必须等于账本里那一代的 generation** ——
否则就是"拿 A 代的 manifest 描述 B 代的内容"。

## 5. T4 · 14 个故障场景

| # | 场景 | 注入方式 | 期望行为 |
|---|---|---|---|
| 1 | 打包中途失败 | 打完 N 个成员后抛错 | 目标路径没有 `gen-*.tar.gz`，只有 `.part` 被清掉 |
| 2 | 打包时磁盘满 | 写入抛 `OSError` | 同上；错误消息说清是哪个文件 |
| 3 | 上传被截断 | 只发前一半字节 | Warden 400 `checksum_mismatch`，归档目录不留文件 |
| 4 | 归档被改一个字节 | 翻转 1 字节 | 同上 |
| 5 | 落位中途失败 | 复制第 2 个文件后抛错 | 目标 `data/` 无半份文件；`.molt-restore-incomplete` 在 |
| 6 | 目标库有非空 WAL | 造 1 字节 `-wal` | `NeedsHuman` 拒绝，原文件一个不动 |
| 7 | 账本被截断 | 把 `state.json` 写成半个 JSON | `Fatal` 明确报"文件坏了"，不静默重建 |
| 8 | 两个壳同时抢租约 | 两个真子进程 | 一个成功、一个 `LeaseHeld`（已有） |
| 9 | 旧 epoch 写入 | `accept_write` 收到更小的 epoch | `EpochStale` 拒绝（已有） |
| 10 | 壳不发心跳 | 只保留旧心跳 | `/where` 标"哑了"，不冒充在线（已有） |
| 11 | 时钟倒退 | 把 warden 时钟拨回 1 小时 | 租约判定仍靠"到期时刻"，不出现永久租约；epoch 单调 |
| 12 | 账本写入时盘满 | `fsync` 抛 `OSError` | 抛 `Fatal`；`state.json` 仍是上一版可读内容 |
| 13 | manifest 缺 `generation` | 删字段 | `land` 拒绝 |
| 14 | manifest 类型错 | `generation = "abc"` | `land` 拒绝 |

「已有」的三条不重写实现，只在矩阵里**引用现有测试**，让这张表成为唯一的索引。

| 不做 | 为什么 |
