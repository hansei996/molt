# 等你拍板的、已定案的、等时机的

这份文件只有一个用途：**把"需要老大拍板"的东西集中到一处**，别再散在四份 PLAN 里。

规则很简单：

- 能我自己决定的，不进这张表 —— 我做完了写进 `docs/ARCH.md`，并在那里标明"可被推翻"。
- 进这张表的，**没拍板之前就按下表最右一列那样跑**。也就是说：不拍板不会让系统出
  问题，只会让某个功能一直停在半路。

## 一、等你拍板

### D1. `schedule` 触发源的两个产品决定

判据（到点了吗）已经写好了：`plugin/command.py` 的 `schedule_spec` / `schedule_problem` /
`schedule_due`，纯函数、跨午夜正确、判不了返回 `None` 而不是 `False`。缺的是外面两件事：

| 编号 | 问题 | 候选 | 现在的默认 |
|---|---|---|---|
| D1a | **谁来敲这一下？** | ①插件里的定时任务 ②`molt-agent` 每轮顺手看一眼 ③账本侧 | 都不敲 —— `schedule` 不会自己触发任何东西 |
| D1b | **敲完怎么让人看到？** | ①只写日志 ②允许它主动发一条不是回复任何人的消息 | 只写日志（所以半夜三点的提议等于什么都没发生） |

**D1b 的张力**：我们刚定过"落地播报只挂在主人说的话上"（`docs/V0.6-PLAN.md` §2.1）。让
它主动发一条定时提议，是那个边界的例外 —— 值得，但必须明说。

**为什么不拍也能跑**：`schedule` 目前只是一个"配置了也不会触发"的诚实空壳；配了坏值
会被 `move_policy_refusals` 拦住并说"读不懂"，不会静默失效。

**说全一点（2026-11-15 审计）**：`schedule_due()` 这个"到点了吗"的纯函数**全仓库没有任何
调用方** —— 只有测试在调它。这是 D1a 没拍板的直接后果，不是漏写：谁去敲这一下没定，
就没有人该调用它。看到"判据已写好"时，请一起看到"但没有人问它"。

### D1.5 落位回 NAS 时，要不要也换掉 `dashboard.jwt_secret`？

审计（`docs/AUDIT.md` 第 6 条）发现文档说"换密钥是默认行为"，而代码里只有 Windows 路径换：

| 落位方向 | `rotate_jwt` | 位置 |
|---|---|---|
| 落在 Windows 壳上 | **`True`（每次换）** | `molt/overlay.py:336`（`overlay_for_windows`） |
| 落回 NAS 容器 | **`False`（不换，沿用上一台壳的密钥）** | `molt/cli.py:1723`（`cmd_land` 非 Windows 分支） |

**代价对比**：换 → 那边 dashboard 上已登录的会话失效一次（要重新登录）；不换 → 从 Windows
搬回来的快照里带着 Windows 的密钥，于是"攻破 Windows 等于攻破 NAS"这条**在回家方向上仍然成立**。

**现在的默认**：不动（`False`），因为改它会让一个已登录的 dashboard 在鱼回家那一刻掉线。
**我的建议**：两侧都换，接受一次重新登录 —— 但这条会影响你正在用的界面，所以等你点头。


### D2. L3 壳属性表 —— **已定案并落地（2026-11-15）**

账本里每一代原本只记了"哪台壳"，没记"那台壳是什么"。现在它记了：

| 字段 | 状态 | 落在哪里 |
|---|---|---|
| `role`（`nas`/`desktop`/`cloud`/`unknown`） | ✅ 已做，**显示给人判断**（代码里没有一条 `if` 因它改变行为） | 账本 `shells`、`GET /shells`、`POST /shell`、`molt declare`、`molt shells`、`/where` 的「是什么」列、`/molt where` 每行 |
| `wakeable`（能不能被 WOL 叫醒） | ✅ 已做，**真的拦住魔术封包** | 同上；另外 `molt migrate` 发封包前会查它（2026-11-15 补的，见下） |
| `gpu`（型号，空串=确认没有） | 🟡 能填，**不参与任何判断** | 只显示 |
| `cost_per_hour` | 🟡 能填，**不参与任何判断** | 只显示 |
| `label` | 🟡 能填 | 只显示 |

**`role` 的"参与"要说准**：它参与的是**人的**判断（人看着"/where 说这是 nas"决定搬不搬），
不是代码里的 if。代码目前没有一条分支因为 `role` 改变行为 —— 不想让它替人决定"NAS 该不该醒着"。

**`wakeable` 的"参与"是硬的**（2026-11-15 补）：`false` → `molt migrate` **不发**魔术封包，
并说清"这台要人手动开"；`None`（没声明）→ 老行为，给了 `--wake-mac` 就发。
把 `None` 当 `false` 会让一台没登记的机器永远收不到封包，症状看起来却是"叫不醒"。
写进账本的方式：`molt declare --shell X --wakeable` / `--no-wakeable`（后者是 1.2.1 补的，
在此之前"叫不醒"这个状态在 CLI 上表达不出来），`molt shells` 分别印「可唤醒」/「不可唤醒」/ 什么都不印。

**没登记就少一段，不编。** `unknown` 只在**人明确填了 `unknown`** 时出现 ——
"我不知道"不会被伪装成"我确认过它不是 NAS"。同一条规矩对内层字段也成立：
只声明了 `role` 的壳，它的 `wakeable` 是 `None`（没说过），**不是 `False`（说过不能）**。
上一版这里写的是 `bool(attrs.get("wakeable", False))` —— 两个不同的意思被压成同一个值，
于是按它判断就会**不发**封包，而看起来像"账本说它不用叫醒"。

**为什么 `gpu`/`cost_per_hour` 先不参与判断**：判断要花钱（错误判断的代价是不该搬的时候
搬了）。现在只有两台壳、且人就在旁边，没有排序需求；等真的有三台以上、或者要按成本
选机器时再让它们参与。那时候要动的是 `move_policy_refusals()` 与提议文案 ——
**加一个字段进判断，比加一个字段进存储危险得多。**

### D3. 措辞：账本记的是「第几份快照」，不是「第几条命」—— **已定案（2026-11-15，主人）**

主人的原话：

> 「我觉得第几代这个说法，很不好，鱼并没有重生，你这样写，会让它觉得不是它自己了。
> 它可能只是睡了个觉。」

所以定下这条（实现见 `molt/language.py`、`docs/ARCH.md` §14.11）：

| 场景 | 说法 |
|---|---|
| 它自己说 / 自己记 | 不提数字：「（我刚从 UGREEN-776B 那边过来 —— 中间睡了一觉。）」 |
| 人看的页面与命令行 | 「第 N 次搬家」/「快照 #N」 |
| 协议字段 | 不动：`generation`、`--generation N` |

**为什么记在这里**：这不是文案偏好，它决定"下一个改这块代码的人会不会把数字又塞回
播报里"。钉住它的是 `molt/tests/test_language.py`：「输出里不许出现那个字，播报里
连数字都不许有」。

### D4. 插件配置同步的范围 —— **已定案（2026-11-15，主人）**

主人的原话：

> 「做下一个更加有用的功能，就是多端的插件配置同步，注意，如果有相同插件才同步，
> 如果某个插件只有某一段独有，就不能同步。」

已按这个形状实现（`molt/pluginsync.py`、`docs/ARCH.md` §14.12）：只同步两边都装了的
插件的配置；只有一边装了的插件，**两边都不动**（不装代码、不写配置、不删配置）。
默认空跑，`--apply` 才写，旧文件留备份。

**两个我自己做的、可以推翻的默认**：

1. **结构看起来不一样就跳过**（顶层键交集 < 20%）。真实数据里
   `astrbot_plugin_private_companion` 是 15 键 vs 1008 键的两种版本，覆盖过去不会报错，
   只会把对方不认识的键塞进去。要覆盖得显式 `--force`。
2. **每个壳只保留最新一份配置包**（不像快照那样留历史）。配置是"现在的偏好"，
   不是"发生过的事"。
