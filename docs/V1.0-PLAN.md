# v1.0 —— 可开源发布

> 目标（用户 2026-11-15 11:26 下达）：**把 molt 推到 v1.0 可开源发布**。
> 验收标准：**陌生人照文档能一条命令装起来、能看见迁移过程**。
>
> 明确不做的两件（需要老大配合）：QQ 落地播报实测、`memory_companion` 记忆档位取舍。
> 断点续传仍是最低优先级。

---

## 0. 为什么是这四件事

v0.5 让「装得起来」第一次成立，但它成立的范围是**仓库 + 一个已经会 Python 的人**：
`git clone` → `pip install -e .` → 手写三份 JSON。而且「能看见迁移过程」这件事
目前只有两种形态：命令行上一行行日志，和一张 `/where` 的静态表格。
对一个还没见过这个项目的人来说，**「它真的搬过去了」这句话目前是没有证据的**。

v1.0 要补的正是证据与入口：

| 缺什么 | 补什么 | 谁来验收 |
|---|---|---|
| 一条命令能跑起来 | `Dockerfile`，`docker run` 起 Warden | 陌生人只在有 docker 的机器上 |
| 「迁移」只存在于日志里 | `molt timeline` / `GET /timeline`：把代次、字节、谁推的、谁取的画成一条时间轴 | 打开一个 HTML 就能看 |
| CI 有两个同名 workflow | 合成一个，加上 wheel / docker / 陌生人演练 | GitHub 上四次绿 |
| 文档是给作者自己看的 | README 首屏一条命令 + INSTALL 的 docker 一节 | 照做能成 |

## 2. 已知的产品取舍（**停下来等老大拍板**）

### 2.1 守护进程要不要打进 pip 包

现状：`pip install molt` 只装 `molt` 这一个包（Warden + CLI），
而 `tools/molt-agent.py` / `molt-homer.py` / `molt-bounce.py` 是**仓库里的独立脚本**，
它们刻意不 `import molt`（这样能在没有 pip 的 NAS 上裸跑）。

两种做法各有一个真实代价：

- **A. 保持现状**：`pip install` 只给服务端；壳那侧要 `git clone`。
  代价是「一条命令装起来」只对**服务端**成立，对壳不成立。
- **B. 打进包里**：把三个脚本变成 `molt/daemons/*.py`，`tools/*.py` 退化成
  三行的转发脚本，再加 `molt-agent` / `molt-homer` / `molt-bounce` 三个
  console script。
  代价是**破坏「守护进程零 molt 依赖」这条设计**，而它存在的原因很具体：
  NAS 上那台 python 3.10.7 连 pip 都没有，脚本是 `python3 tools/molt-homer.py` 直接跑的。

v1.0 暂时按 **A** 做（不新增风险），把 B 留成 v1.1 的候选，并在 INSTALL 里
明说「壳那侧目前要 clone 仓库」。

### 2.2 发布凭据：镜像与 PyPI 都缺一把 token（**等老大拍板**）

「陌生人一条命令装起来」这句话，现在能成立的是
**`git clone` → `docker build` → `docker run`**（三行，CI 里每次都真跑一遍），
还不是一行 `docker run ghcr.io/hansei996/molt:latest` 或 `pip install molt`。
差的不是代码，是两把凭据：

| 想要的形态 | 卡在哪 | 我需要什么 |
|---|---|---|
| `docker run ghcr.io/hansei996/molt:latest` | 没推过镜像 | 一个有 `write:packages` 的 GitHub token（或你在网页上建一次 package） |
| `pip install molt` | 没发过 PyPI | PyPI 的 API token（或者 `pipx install git+https://…` 这种不走 PyPI 的说法） |

**我没有自己去注册 namespace**：一个名字归谁、以后谁维护，是人的决定，
不是脚本的决定。在那之前文档里写的是能跑的那条路，而且明确写「预构建镜像还没推」。

另外：`gh` CLI 已经在这台机器上登录着（`hansei996`，scopes 含 `repo`/`workflow`，
**不含 `write:packages`**）——所以 `docker push` 现在会 403，不是网络问题。

### 2.3 「迁移过程」要不要做成实时

`/timeline` 是**每次打开重新渲染**的静态快照。做成 SSE 实时流也在能力范围内，
但它会把 Warden 从「只读 + 单文件账本」推向「要维护长连接」，
与本项目「Warden 要能在什么都没有的机器上跑」的约束相冲突。v1.0 不做。

## 2.5 真机证据（2026-11-15）

这一节不是"测试通过"，是**在真机器上跑出来的数字**。

### 时间轴（T1–T3）

```
$ molt timeline --warden-url http://<nas>:6186 --warden-token <token>
✓ 已经搬过 19 次，完成落地 13 次。
  最新一代                   第 19 代
  从哪来                    UGREEN-776B
  谁取走的                   desktop-h2kgiao
  搬到                     ...\dist\_timeline_nas.html
```

那一页 4,893 字节，零外部请求（用 `http://` 计数断言过），
数据全部来自 NAS 上那个真实的 `state.json`（epoch 21、19 代、518.7 MB）。

### 镜像（T4）

```
$ docker build -t molt:smoke .        # 在 NAS 上，docker 20.10.16，无 buildx
Successfully tagged molt:smoke        # 12.6 秒，未拉任何新镜像
$ docker run --rm molt:smoke          # 没给 token
molt: 没有设置 MOLT_TOKEN，账本不敢启动。 ...   exit=78
$ docker run -d -p 6187:6186 -e MOLT_TOKEN=... molt:smoke
Up 37 seconds (healthy)
status=200  timeline=200  noauth=401
```

容器以 `uid=10001(molt)` 跑，不是 root；`/var/lib/molt` 是唯一可写目录。

### 指纹这一列曾经永远是空的

做时间轴时才发现：账本里的 `manifest_sha256` **从来没有被写过值**。
所以那一列一直显示 `—` —— 空着的那一列比没有这一列更糟，因为「指纹」
两个字让人以为这里能核对。

修法：收归档时算出来的 sha256 写在归档旁边
（`archives/gen-000019.tar.gz.sha256`），时间轴优先读它。
为什么不是塞进 `GenerationRecord`：上传的顺序是**先传字节、后登记 generation**，
收归档那一刻账本里还没有这一代。硬塞只有两种办法——给账本加一张
"待认领指纹"的表，或者 push 之后回头再补一条（忘了补就永久缺失，而且不报错）。
两个都比"指纹跟着它描述的那份字节走"更容易出错。

早期那 19 代没有 sidecar，所以还是 `—`。**那是诚实的结果**：那时候确实没记。

## 2.6 CI 首跑抓到的三个错（为什么「会红的 CI」值得做）

合并后的第一个 run 是**七个 job 里红五个**。三个错都只在别人的机器上出现：

| 错 | 形状 | 为什么本地看不见 |
|---|---|---|
| `extractall(..., filter="data")` | `TypeError` on Python 3.10.11 | 我的机器是 3.13；`filter` 是 3.12 才有的参数 |
| 自愈测试真的去跑 `platform-switch.py` | `boots == []` | 我这儿 `G:\molt-fish` 存在、脚本返回 0，CI 上不存在 |
| `Warden` 默认根目录是 `/mnt/dm-0/astrbot/_molt` | `doctor` 抛异常 | 那是**作者 NAS 上的路径**，Windows 上走了另一个分支 |

第三个是最难看的：`molt/warden.py` 的 docstring 里写着
"为什么不能只写死 `/mnt/dm-0/astrbot/_molt`"，然后在 Windows 上分了平台、
把 POSIX 那条留成了那台机器的路径。**写下了规则，却没遵守它。**
而它伤害的正是这一版要服务的人：陌生人照文档第一次敲 `molt init --role warden`。

两条教训：

1. **没人看的 CI 等于没有 CI。** 上一版的四次矩阵从 v0.5 起就一直红着，
   而我在本地跑绿了 849 个测试就当成"完成"。红四周没人看，比没有 CI 更糟 ——
   它让人以为自己有安全网。
2. **"装得起来"必须由别人的机器来证明。** 这三条本地全绿，CI 全红，
   而 CI 才是那个"别人"。

## 3. 不在这一版做

- 断点续传（4.5 MB 的归档，重传成本远低于维护续传状态）
- 第二宿主适配器（v0.6 的通用化，要选一个有真实消费者的第二壳）
- `memory_companion` 记忆档位（要改别人的插件行为，且需要老大先决定）
- 实时 `/timeline`（见 2.3）
